# 部署指南

三种方式，按你的环境选。

---

## 方式 A：Linux + systemd（推荐）

```bash
# 1. 上传
scp -r backend/ frontend/ root@YOUR_HOST:/tmp/ai-deploy/

# 2. 安装（默认 /opt/autoinstall-backend，端口 3809）
ssh root@YOUR_HOST
cd /tmp/ai-deploy/backend
bash deploy/install.sh --port 3809 --token '你的口令'

# 3. 验证
curl -s -X POST -d 'key=hq' http://127.0.0.1:3809/api/user/getAppInfos | head -c 120
```

`install.sh` 会：装到 `/opt/autoinstall-backend`、写 systemd unit（`enabled` + `Restart=always`）、
启动并自检、打印管理台地址与口令。

管理：

```bash
systemctl status|restart autoinstall-backend
journalctl -u autoinstall-backend -f
tail -f /opt/autoinstall-backend/data/access.log      # 谁在拉任务
tail -f /opt/autoinstall-backend/data/records.jsonl   # 谁装完了
```

---

## 方式 B：Windows 侧一键（scp + ssh）

```powershell
cd backend\deploy
.\deploy.ps1 -Server YOUR_HOST -User root -KeyFile C:\keys\id_ed25519 `
             -RemotePort 3809 -Token '你的口令' -BuildClient
```

它会：打包 → `scp` 上传 → 远端执行 `install.sh` → 本地公网验收 →（`-BuildClient`）顺便把客户端
`ApiUrl` 改成 `http://YOUR_HOST:3809` 重新编译出来。

---

## 方式 C：Docker

```bash
cd backend
docker compose up -d
# 端口 3809，数据挂载在 ./data
```

## 公网访问：反代 / 防火墙

### 云安全组没开 3809 时，用 nginx 反代（端口 80/443 通常已开）

```bash
# 把 /api/ 和 /admin 反代到 127.0.0.1:3809（会先备份原 vhost，nginx -t 通过才 reload）
bash backend/deploy/nginx_proxy.sh
```

宝塔面板环境可直接跑；非宝塔请改脚本里的 `CONF` 路径为你自己的 server 块。

### 建议上 HTTPS

```nginx
server {
    listen 443 ssl http2;
    server_name cad.example.com;
    ssl_certificate     /etc/ssl/fullchain.pem;
    ssl_certificate_key /etc/ssl/privkey.pem;

    location ^~ /api/  { proxy_pass http://127.0.0.1:3809; proxy_set_header X-Real-IP $remote_addr; }
    location ^~ /admin {
        allow 203.0.113.10;      # 只允许自己
        deny  all;
        proxy_pass http://127.0.0.1:3809;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

然后把客户端 `ApiUrl` 改成 `https://cad.example.com`（客户端 `IgnoreInvalidCertificates = true`，
自签证书也能用）。**必须**带上 `X-Real-IP` / `X-Forwarded-For`，否则 `access.log` 里全是 127.0.0.1。

## 上线检查清单

1. `curl -X POST -d 'key=hq' http://HOST:PORT/api/user/getAppInfos` 有 2 条
2. 管理台能打开，口令正确，能新建一条任务
3. `users.json` 里删掉演示账号，加上自己的授权码
4. 客户端在测试机跑通一条无害任务（`PRINT` + `COPY_FILE`），管理台能看到上报
5. 备份 `data/tasks.json`（导出任务包 zip 也行）
6. `/admin` 加 IP 白名单或改到非公开端口

## 常见问题

| 现象 | 处理 |
|---|---|
| 公网连不上 3809 | 云安全组没放行；或改用 nginx 反代（方式见上） |
| 客户端提示"获取安装数据异常" | 服务端没起 / 地址写错 / 端口不通；看 `journalctl -u autoinstall-backend` |
| 客户端一直"正在获取安装数据" | `ApiUrl` 末尾多余斜杠会得到 `//api/...`，反代层能处理，直连 3809 也可以 |
| 任务执行了但没装 | 看管理台「安装上报 → other」里的逐条日志；常见是 md5 不匹配（任务被静默跳过） |
| 管理台样式丢失 | `frontend/admin/` 没一起上传，或服务启动时没加 `--web`（会自动回退到内置页面） |
